Accessibility

If the state cannot be perceived, the state is incomplete.

Regulated Infinity Labs treats accessibility as functional correctness. Information, decisions and next actions should not depend on one input method or a visual presentation.

Website approach

  • Semantic HTML, meaningful headings and landmark navigation.
  • A skip link for direct access to main content.
  • Keyboard-visible focus and controls that do not require pointer input.
  • Responsive text and layout that remain usable at narrow widths and zoom.
  • Light and dark themes with the same information hierarchy.
  • Reduced-motion and increased-contrast preferences where supported.
  • Meaningful alternative text for informational imagery.
  • A standard, keyboard-operable language selector.
  • A persistent reader-friendly view that can be switched on or off at any viewport size.

Typography and reader-friendly view

The site’s standard editorial style uses justified body text without automatic hyphenation. Because that presentation is not equally comfortable for every reader, the Reader view control switches body copy to left alignment, increases reading line height, narrows the text measure and linearizes multi-column content where appropriate. The preference is stored locally in the browser and can be reversed at any time.

The reader-friendly view is an additional presentation choice, not a claim that the standard view is inaccessible or that either view has been independently certified.

Conformance target

The website is designed toward WCAG 2.2 Level AA. It has not yet undergone an independent formal audit, so this statement does not claim certified conformance.

PulseRail

PulseRail is being developed with screen-reader operation, explicit state announcements, coherent focus order, clear action hierarchy and non-visual status communication as first-order requirements. Accessibility findings are treated as product defects.

Pre-release limitation

The website and PulseRail remain under active development. Deterministic checks do not replace practical testing with real assistive technologies, so final acceptance must include real-world accessibility review.

Feedback

A permanent public accessibility contact channel will be published before general distribution.

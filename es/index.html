PulseRail · 1.0.0-rc4

De un proyecto Android completo a un build trazable — desde el teléfono.

PulseRail importa un ZIP completo, inspecciona la salud del proyecto, coordina un build privado en GitHub Actions, verifica el artefacto exacto, conserva la identidad de firma y permite una entrega explícita al teléfono o a Wear OS. No busca ser otro botón de Build: busca que el build pueda explicarse.

Release candidate · pruebas del propietario

Compila desde el teléfono. Conserva la evidencia.

Repositorio, commit, workflow run, attempt, artefacto, paquete, versión, hash y firmante forman parte del estado del producto. Un CI en verde es importante, pero no cuenta toda la historia.

Documentación completa

Por qué importa

Un build exitoso todavía puede dejar preguntas peligrosas.

¿Qué fuente produjo este APK?

El artefacto se vincula al repositorio, commit exacto, run y attempt, no solo a un nombre de archivo.

¿Qué aplicación puede actualizar?

El package ID y la línea de firma son identidad de actualización. Si la evidencia no cuadra, el flujo se detiene.

¿La recuperación duplicó trabajo?

Tras perder red o proceso, se reconcilia primero el trabajo remoto existente.

¿Se autorizó exactamente esta reparación?

Safe Build Repair vincula la aprobación a fuente, propuesta, requisitos y conjunto ordenado de cambios.

¿Qué ocurre con la firma?

Una identidad de firma ausente no se sustituye silenciosamente por una nueva solo para poder instalar.

¿Funciona sin visión?

Lector de pantalla, foco, anuncios de estado y siguientes acciones claras son comportamiento del producto.

Principios de ingeniería

Evidencia antes que autoridad.

Verificable por diseño

Los resultados importantes se atan a identidades, hashes, versiones y estado explícito.

Fail closed

La evidencia incierta no se convierte en permiso automático para reparar, volver a firmar, instalar o despachar otra vez.

Recuperar es normal

Los procesos móviles mueren y las redes desaparecen; el modelo transaccional debe asumirlo.

Límites de confianza estrechos

Fuente, build, verificación y firma permanecen separados siempre que el flujo lo permite.

Accesibilidad = corrección

Un estado que solo existe visualmente está comunicado de forma incompleta.

Las afirmaciones siguen a las pruebas

La documentación distingue diseño, implementación, validación determinista y aceptación real pendiente.

Estado actual

Lo bastante interesante para enseñarlo. Todavía no lo bastante terminado para lanzarlo.

PulseRail 1.0.0-rc4 sigue en integración activa y pruebas del propietario. El onboarding final mediante GitHub App, la coherencia completa del producto y la verificación final de release siguen pendientes.

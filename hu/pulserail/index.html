PulseRail · Android build-orkesztráció

Az Android buildednek is legyen bizonyítható eredettörténete.

A PulseRail telefonról visz végig egy teljes Android-projektet az importtól a kontrollált cloud builden át a pontos artifact-ellenőrzésig, az aláírási identitás megőrzéséig és a telefonos vagy Wear OS-es átadásig.

A lényeg: a „workflow sikeres” nem a végső válasz. A PulseRail azt is követi, melyik forrás, run, attempt, artifact, csomag, verzió és aláíró áll a fájl mögött.

Teljes folyamat

Egy projekt. Egy megmagyarázható tranzakció.

A forrás- és tranzakciós identitás az import, vizsgálat, javítás, dispatch, távoli megfigyelés, ellenőrzés és átadás során is megmarad.

01

Import

Egy teljes Android projekt-ZIP fogadása és szerkezeti ellenőrzése.

02

Vizsgálat

A valódi Gradle-root, a projektállapot és a releváns buildkövetelmények meghatározása.

03

Javítás, ha bizonyítható

A Safe Build Repair a pontos forráshoz, javaslathoz, követelmény-bizonyítékhoz, változáslistához és jóváhagyáshoz kötött.

04

Build

A kanonikus GitHub Actions workflow koordinálása privát workspace-ben, tartós tranzakciós állapottal.

05

Megfigyelés és helyreállítás

Hálózati hiba vagy process death után a már létező távoli munka egyeztetése új futás indítása előtt.

06

Ellenőrzés

Repository, commit SHA, run ID, attempt, artifact ID, csomag, verzió, APK-hash és aláíró összekötése.

07

Átadás

Ellenőrzött telefonos APK exportja explicit Android-telepítéshez vagy korlátozott Wear OS telepítési folyamat.

08

Identitás megőrzése

Meglévő alkalmazásnál az eredeti aláíró visszaállítása identitás-helyreállítás, nem kényelmi újrakulcsolás.

Build Doctor

A diagnózis nem jogosultság.

A Build Doctor külön kezeli a projektállapotot, a követelményeket, a determinisztikus biztonságos javítást és a bizonytalan fejlesztői beavatkozást.

A követelményeknek szemantikájuk van

Egy követelmény lehet minimum, maximum, egzakt verzió, tartomány, támogatott halmaz, inventory, checksum, logikai feltétel vagy tanács. A minimum nem jelent automatikusan egzakt downgrade-célt.

Friss bizonyíték kell

Az elavult, ellentmondó vagy nem támogatott követelményforrás diagnosztikát adhat, de nem jogosít automatikus javításra.

Az eredeti projekt megmarad

A biztonságos javítás copy-on-write revíziót hoz létre, pontos változásokat alkalmaz, majd újraellenőrzi az eredményt.

Védett identitás

Az applicationId, az aláírói lánc és más védett projekt-határok nem íródnak át csendben.

Artifact provenance

Az, hogy „ez az APK ebből a projektből készült”, ellenőrizhető állítás legyen.

Forrásidentitás

Repository, ág és pontos commit SHA.

Futásidentitás

Workflow-run, attempt és dispatch-identitás.

Artifact-identitás

Artifact ID, csomag, verzió, SHA-256 és aláíró tanúsítvány.

A fájlnév lemásolható. A zöld státusz tartozhat másik attempthez. Erősebb a bizonyíték, ha több, egymástól független identitásnak egyszerre kell egyeznie.

Telefon és Wear OS

Ellenőrzött forrás. Explicit cél.

Telefon

Az ellenőrzött APK az Android Letöltések közé kerül, és a felhasználó indítja a rendszer normál telepítési folyamatát.

Wear OS

A telepítés előtt a rendszer újraellenőrzi az artifactot, a kiválasztott hitelesített órát, az alkalmazás identitását és a telepítési készültséget.

GitHub-kapcsolat

Böngészős GitHub App onboarding felé.

Az RC4 célja a böngészőből induló PulseRail GitHub App folyamat. A szükséges biztonsági és broker policy-határok már léteznek a forrásban.

Jelenlegi korlát: a Setup Wizardban még megtalálható a történeti fine-grained PAT-first út. A GitHub App termékintegráció befejezése továbbra is RC4 blocker, ezért a weboldal nem állítja, hogy a migráció kész.

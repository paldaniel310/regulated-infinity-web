PulseRail · privacy

Pre-release privacy information

Draft status: PulseRail 1.0.0-rc4 is still in release-candidate development and owner testing. This page describes the current product design at a high level and is not yet the final production privacy notice.

PulseRail is designed to process only the information needed to import, build, verify, recover and deliver the Android project selected by the user. Important product state is kept explicit so that interrupted or ambiguous operations can be reconciled rather than repeated blindly.

Information handled by PulseRail

  • Project content and project metadata: the Android project selected by the user, source identity, package information and build configuration needed to perform the requested workflow.
  • Build and artifact identity: repository and revision identifiers, workflow run and attempt information, package and version identity, artifact identifiers, cryptographic hashes and signing-certificate identity used for verification.
  • Connection and recovery state: the minimum state needed to connect to supported external services, recover interrupted work and prevent duplicate operations.
  • Device state: when Wear OS installation is used, bounded information about the selected authenticated watch and installation readiness. The product design avoids using raw device identifiers as durable audit identifiers where a pseudonymous representation is sufficient.
  • Local settings and diagnostics: product configuration, transaction state and bounded diagnostic records needed for support, recovery and verification.

External services

PulseRail uses GitHub as the build-workspace and workflow platform. The RC4 target is browser-based GitHub App onboarding for normal use. Optional signing recovery is designed to use the exact Google account explicitly selected by the user and the application's private Google Drive application-data space.

The final production notice will identify the production service providers, processing purposes, legal bases where applicable, international-transfer safeguards where applicable and retention rules after those production integrations are finalized.

Credentials and secrets

The Android client is designed not to embed service private keys or client secrets. Sensitive authentication material is not intended to become project content, build artifacts or ordinary diagnostic output. The product also separates project signing identity from the application's own build identity.

Retention and deletion

Local project, transaction and diagnostic state is intended to remain under explicit product controls and to be removable through the relevant cleanup or project-removal actions. GitHub build history and workspace retention are governed by the product's bounded cleanup behavior and by GitHub account settings. Final production retention periods will be stated before general distribution.

Wear OS privacy boundary

The Wear OS installation feature is intentionally scoped to a verified PulseRail artifact and the watch selected for that operation. It is not designed as a general remote device-management or package-inventory tool.

Your choices

Optional integrations are intended to require explicit user action. Signing recovery is account-first, and the selected account is part of the recovery context. Installation and repair operations that affect important identity or project state require explicit user review rather than being silently inferred.

Before general release

The final privacy notice will add the controller identity and contact channel, complete provider list, purposes and legal bases of processing, retention periods, data-subject rights and any jurisdiction-specific disclosures required for the production release.

PulseRail · privacy

Privacy boundaries should be as explicit as build boundaries.

Draft status: PulseRail 1.0.0-rc4 is still in release-candidate development and owner testing. This page describes the current design and is not the final production privacy notice.

PulseRail is designed to handle the information needed to import, build, verify, recover and deliver the Android project selected by the user. Important transaction state is kept explicit so interrupted work can be reconciled rather than repeated blindly.

Information handled by PulseRail

  • Project content and metadata: the selected Android project, source identity, package information and build configuration needed for the requested workflow.
  • Build and artifact identity: repository/revision identifiers, workflow run and attempt information, package and version identity, artifact identifiers, hashes and signing-certificate identity used for verification.
  • Connection and recovery state: bounded state needed to connect to supported services, resume interrupted work and prevent duplicate operations.
  • Wear OS state: when watch installation is used, bounded information about the selected authenticated watch and readiness state.
  • Local settings and diagnostics: product configuration, transaction state and bounded diagnostic records needed for recovery and support.

External services

PulseRail uses GitHub as its build-workspace and workflow platform. The RC4 target is browser-based GitHub App onboarding for normal use; that product cutover is still being integrated. Optional signing recovery is designed around the exact Google account explicitly selected by the user and the application’s private Drive application-data space.

Credentials and signing material

The Android client is designed not to embed service private keys or client secrets. Authentication material is not intended to become project content, build artifacts or ordinary diagnostic output. Project signing identity is treated separately from PulseRail’s own build identity.

Retention and deletion

Local project, transaction and diagnostic state is intended to remain under explicit cleanup controls. Remote build history remains subject to the product’s bounded cleanup behavior and the user’s GitHub account settings. Final production retention periods will be stated before general distribution.

Wear OS boundary

The watch-install feature is scoped to a verified PulseRail artifact and the watch selected for that operation. It is not designed as a general remote device-management or arbitrary package-inventory tool.

Your choices

Optional integrations require explicit user action. Signing recovery is account-first. Repair and installation actions that affect important project or identity state require explicit review rather than silent inference.

Before general release

The final notice will add controller identity and contact details, the complete production provider list, purposes and legal bases where applicable, retention periods, data-subject rights and required jurisdiction-specific disclosures.

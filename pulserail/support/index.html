PulseRail · support

Support and diagnostics

Release-candidate status: PulseRail 1.0.0-rc4 is under owner testing and is not yet generally available.

Before reporting a problem

  1. Confirm the exact PulseRail version.
  2. Note the screen or workflow stage where the problem occurred.
  3. If a build was involved, keep the build or run identity shown by PulseRail.
  4. Use the status refresh or recovery action when the product offers one.
  5. Include only information relevant to the problem.

Useful context

A useful report normally includes the app version, Android version, device model, visible PulseRail state or error category, approximate time of occurrence and relevant build or run identity when available.

Build and recovery problems

PulseRail is designed to preserve build transaction identity across network loss and process death. When an operation appears interrupted, prefer the product’s recovery or refresh path over starting replacement work manually.

Signing problems

If PulseRail reports that the required signer is missing or incompatible, treat that as an application-identity issue. The intended path is to restore the correct update identity.

Wear OS problems

If the artifact or selected watch changes, return to the readiness flow and allow PulseRail to check the operation again.

Accessibility issues

Accessibility defects are product defects. A useful report identifies the assistive technology, affected control, observed result and expected result.

Public support channel

A permanent public support address and reporting process will be published before general distribution.
